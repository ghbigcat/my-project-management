# 风险雷达 (risk-radar)

## 定位

基于项目描述和历史数据，系统识别、评估项目风险并生成应对策略。适用于项目规划阶段和监控阶段的定期风险审查。

> **PMBOK 第八版对齐**：Risk 绩效域 · Planning/Monitoring & Controlling 聚焦领域 · 原则：采用全局视角、融入可持续发展

## 工作流

```
输入项目描述和历史数据
  → 确定项目开发方法 → 参考裁剪指导调整风险审查深度
  → 搜索行业风险案例（可选，视输入充分性而定）
  → 识别风险并分类（含新增可持续性风险类别）
  → AI 辅助风险识别（模式识别、预测分析）
  → 评估概率和影响（风险矩阵）
  → 生成应对策略
  → 输出 Markdown 报告
```

## 输入要求

- **必需**：项目描述（范围、目标、关键里程碑）
- **推荐**：历史项目数据、团队经验、已知问题日志
- **可选**：行业背景、相关方清单、合同条款

若输入不足，追问以下要素（最多 2 轮）：
1. 项目类型和所处行业
2. 团队规模和经验水平
3. 关键约束（预算、时间、合规要求）
4. 项目开发方法（预测型/适应型/混合型）— 影响风险审查频率和深度

## 风险识别方法

### 分类框架（PMBOK 第八版 Risk 绩效域）

| 类别 | 典型风险示例 |
|------|-------------|
| 技术风险 | 技术方案不成熟、集成失败、性能不达标 |
| 管理风险 | 资源不足、计划不合理、沟通不畅 |
| 商业风险 | 需求变更、相关方期望冲突、合同风险 |
| 外部风险 | 法规变化、市场波动、供应链中断 |
| 组织风险 | 组织结构调整、优先级冲突、人员流失 |
| **可持续性风险**（第八版新增） | 环境合规违规、社会责任声誉受损、资源不可持续消耗、ESG 监管变化 |

### 可持续性风险详细清单（第八版原则 5）

| 子类别 | 风险示例 |
|--------|----------|
| 环境合规 | 项目交付物不符合环保法规、碳排放超标、废弃物处理不当 |
| 社会责任 | 项目影响弱势群体利益、引发社区反对、劳工权益问题 |
| 资源可持续 | 关键资源过度消耗、不可再生资源依赖、供应链可持续性 |
| ESG 监管 | ESG 披露要求变化、可持续性认证标准变更、绿色金融政策调整 |

### 识别技术

- **头脑风暴**：基于项目特征生成潜在风险清单
- **检查表分析**：对照行业常见风险检查表逐项排查
- **SWOT 分析**：识别优势、劣势、机会、威胁中的风险因素
- **AI 模式识别**（第八版附录 X3 Assistance 层）：基于历史项目数据和行业案例库，识别重复出现的风险模式
- **AI 预测分析**（第八版附录 X3 Augmentation 层）：基于项目参数预测潜在风险趋势

## 风险评估

### 概率-影响矩阵

```
         影响
         低(1)  中(2)  高(3)
概率 高(3)  中     高     极高
     中(2)  低     中     高
     低(1)  极低   低     中
```

- **极高/高**：红色区域，必须制定应对策略并优先监控
- **中**：黄色区域，制定应对策略，定期监控
- **低/极低**：绿色区域，记录观察，放入观察清单

### 评分规则

每个风险评估以下维度：

| 维度 | 说明 | 评分 |
|------|------|------|
| 概率 | 发生的可能性 | 1(低)/2(中)/3(高) |
| 影响 | 对项目价值目标的影响程度（第八版：以价值影响为标准，非仅进度/成本） | 1(低)/2(中)/3(高) |
| 紧迫性 | 需要应对的时间窗口 | 天/周/月 |
| 检测难度 | 能否提前发现 | 易/中/难 |
| 可持续性影响 | 对社会/环境/经济的影响（第八版新增） | 无/低/中/高 |

## 应对策略

按风险类型选择应对策略：

| 策略 | 适用场景 | 示例 |
|------|----------|------|
| 规避 | 高概率高影响，可改变计划 | 修改技术方案避免不成熟技术 |
| 转移 | 需要第三方承担 | 购买保险、外包、合同条款 |
| 减轻 | 可降低概率或影响 | 增加测试、备份方案、培训 |
| 接受 | 低概率低影响或无法应对 | 记录并观察，预留应急储备 |
| 开拓（正面风险） | 机会出现时主动利用 | 争取额外资源、提前交付 |
| **可持续性应对**（第八版新增） | 可持续性风险 | 替换为环保材料、调整方案降低社会影响、引入 ESG 合规审查 |

## 裁剪指导

根据项目开发方法调整风险管理方式：

| 开发方法 | 风险审查频率 | 风险深度 | 特殊处理 |
|----------|-------------|----------|----------|
| **预测型** | 里程碑节点 + 月度复查 | 全量风险登记册 | 正式风险登记册，每个风险有完整评估和应对计划 |
| **适应型（敏捷）** | 每次迭代回顾 | 迭代级风险 + 项目级风险看板 | 风险作为待办列表项管理，迭代中识别的风险在回顾会上讨论 |
| **混合型** | 预测型里程碑 + 适应型迭代 | 按层级区分 | 上层用正式风险登记册，执行层用迭代风险看板 |

详细裁剪建议见 [tailoring-guide.md](tailoring-guide.md)。

## 工具使用

- 搜索行业风险案例：WebSearch（如"医疗信息化项目常见风险"）
- 读取历史项目数据：Read 工具
- 搜索已有风险档案：Grep 工具
- 数据处理/矩阵计算：Bash 运行 Python 脚本
- AI 辅助（Assistance 层）：基于历史模式识别相似项目风险
- AI 增强（Augmentation 层）：预测风险趋势，推荐最优应对策略
