# 绩效度量器 (evaluation)

## 定位

把"做完了"转化为"做得怎么样"。为项目设计可度量的指标体系、前置定义验收标准、执行度量并给出评估结论。适用于项目周期性评估、里程碑验收、阶段复盘三个场景。

> **PMBOK 第八版对齐**：Finance + Governance 绩效域 · Monitoring & Controlling 聚焦领域 · 原则：聚焦价值、将质量融入过程和交付物

## 工作流

```
输入项目目标 + 交付物清单 + 既有基线
  → 判断开发方法 → 参考裁剪指导确定度量密度
  → 建立三层指标体系（价值层 / 交付层 / 过程层）
  → 为每个指标写"指标定义卡"（口径唯一、可复核）
  → 确定数据来源与采集频率（与 observability 模块共用同一套口径）
  → 计算偏差指标（EVM：SV / CV / SPI / CPI）
  → 生成验收标准与测试用例
  → 出具评估结论（合格 / 有条件合格 / 不合格）
  → 输出 Markdown 报告
```

## 输入要求

- **必需**：项目目标（价值目标，非仅交付物）、交付物清单
- **推荐**：进度基准、成本基准、既有 KPI 表、上一周期评估结论
- **可选**：行业基准值、客户（药企）考核条款、SLA 文本

若输入不足，追问以下要素（最多 2 轮）：
1. 项目类型与行业（医疗健康服务 / IT / 制造 / 金融）
2. 客户方的考核口径与结算方式（如按服务量付费）
3. 关键约束（预算、周期、合规要求）
4. 项目开发方法（预测型 / 适应型 / 混合型）— 决定度量频率与指标数量

## 三层指标体系

只做"过程层"度量会失去方向，只做"价值层"度量会失去抓手。三层必须同时存在，且**下层为上层的解释变量**。

| 层次 | 回答的问题 | 通用指标示例 | PSP / RRMM 患者服务场景示例 |
|------|-----------|-------------|---------------------------|
| **价值层** | 价值交付了吗 | 客户满意度、业务目标达成率、ROI | 药企满意度评分、项目对患者服务可及性的改善、续约意向 |
| **交付层** | 产出交付了吗 | 里程碑达成率、验收一次通过率、交付物完整率 | 阶段交付物按时提交率、审计一次通过率、培训完成率 |
| **过程层** | 过程在轨吗 | SLA 达成率、人效、数据上报及时率 | 服务按时完成率、专员人均服务量、患者随访记录及时率、AE 上报及时率 |

> **医疗场景边界**：患者服务类指标以**服务过程与依从性**为对象（触达率、随访完成率、脱落率、教育材料触达）。护理人员仅提供患者服务，不从事诊疗，因此**不设任何以诊疗结局为口径的指标**。

## 指标定义卡（必填）

每一个进入报告的数字，都必须先有一张定义卡。**一个指标只能有一个口径**，口径变更须记录版本号。

| 字段 | 说明 |
|------|------|
| 指标编号 | 唯一标识，如 KPI-P-003 |
| 指标名称 | 中英双语，避免歧义简称 |
| 业务口径 | 一句话说清"算什么、不算什么" |
| 计算公式 | 分子 / 分母，含取整与舍入规则 |
| 数据来源 | 系统名 + 具体表 / 字段，或纸质记录编号 |
| 采集频率 | 日 / 周 / 月 / 事件触发 |
| 目标值 | 达成线 |
| 阈值 | 黄线 / 红线（与 observability 模块联动） |
| 责任人 | 唯一负责人，不可写"团队" |
| 复核人 | 与责任人分离 |

## 数据校验（硬要求）

进入结论的每一个关键数字，必须**双源独立印证**，不得单源采信。

| 数据点 | 来源 A | 来源 B | 是否一致 | 差异说明 |
|--------|--------|--------|----------|----------|
| 例：9 月服务完成例数 | 项目管理台账 | 客户方月度对账单 | 待填 | 冲突时以客户方对账口径为准并在正文标注分歧 |

规则：
- 时效性敏感数据（价格、政策、班次、报销目录）优先查官方源原文，不用二手转述。
- 两源冲突时，以官方源 / 客户方对账口径为准，并在报告正文中明确标注分歧与处理方式。
- 无法双源印证的数字，标注为"单源，待核实"，不得直接进入结论。

## EVM 偏差指标

| 指标 | 公式 | 含义 |
|------|------|------|
| PV | 计划价值 | 到某时点按计划应完成的价值 |
| EV | 挣值 | 实际完成工作的价值 |
| AC | 实际成本 | 实际发生成本 |
| SV | EV − PV | 进度偏差（正值提前） |
| CV | EV − AC | 成本偏差（正值节约） |
| SPI | EV / PV | 进度绩效指数（<1 落后） |
| CPI | EV / AC | 成本绩效指数（<1 超支） |

**服务型项目折算规则**：在按服务量付费模式下，`EV = 已完成服务量 × 合同单价`；`PV = 计划服务量 × 合同单价`。不得直接沿用工程量口径。

### 偏差判定

| SPI / CPI | 判定 | 动作 |
|-----------|------|------|
| ≥ 0.95 | 在轨 | 常规记录 |
| 0.85 – 0.95 | 偏离 | 项目经理 24 小时内出纠偏措施 |
| < 0.85 | 严重偏离 | 上报 PMO，当日响应，评估是否触发变更或 CAPA |

## 验收标准与测试用例

验收标准**前置**——在需求拆解阶段即定义，不允许在交付前补写。

### 验收标准要素

| 要素 | 要求 |
|------|------|
| 可判定 | 用二值或明确阈值表述，避免"较好""基本完成" |
| 可复现 | 换一个人按同一口径执行，得到同一结论 |
| 有依据 | 每条标准对应一个指标编号或合同条款 |
| 有责任人 | 验收人与被验收人分离 |

## 评估结论分级

| 结论 | 判定条件 | 后续动作 |
|------|----------|----------|
| **合格** | 验收标准全部满足；SPI/CPI ≥ 0.95 | 进入下一阶段，归档度量数据 |
| **有条件合格** | 核心标准满足，非核心项存在偏差 | 列整改清单 + 截止日期 + 唯一责任人，下周期复验 |
| **不合格** | 核心验收标准未满足 | 触发变更请求或 CAPA，重新制定计划 |

## 裁剪指导

| 开发方法 | 度量频率 | 指标数量 | 评估报告形式 |
|----------|----------|----------|-------------|
| **预测型** | 里程碑 + 月度 | 全量指标（价值/交付/过程三层齐备） | 正式评估报告，含 EVM 与偏差分析 |
| **适应型（敏捷）** | 每次迭代 | 迭代级 3–5 个指标 + 项目级价值指标 | 迭代度量卡，含完成率与速率 |
| **混合型** | 里程碑按预测型、迭代按适应型 | 分层：上层全量，执行层精简 | 上层评估报告 + 执行层度量卡 |

详细裁剪建议见 [tailoring-guide.md](tailoring-guide.md)。

## 工具使用

- 读取基线文件（进度/成本基准）：Read 工具
- 搜索历史评估结论与指标库：Grep 工具
- EVM 计算、达成率与偏差批量计算：Bash 运行 Python 脚本
- 查询行业基准值 / 官方口径：WebSearch（时效性敏感数据须回溯官方源原文二次印证）
- AI 辅助（Assistance 层）：指标口径一致性检查、验收标准完整性检查
- AI 增强（Augmentation 层）：偏差根因推断、整改优先级排序
