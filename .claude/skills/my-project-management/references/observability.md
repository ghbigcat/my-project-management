# 过程观测器 (observability)

## 定位

持续观测项目运行状态，把**工作绩效数据**逐级转化为**工作绩效信息 → 工作绩效报告**，在偏差扩大之前触发预警。适用于项目全周期的常态化监控，尤其是多项目并行（PMO 视角）时的一致性盯盘。

> **PMBOK 第八版对齐**：Governance 绩效域 · Monitoring & Controlling 聚焦领域 · 原则：采用全局视角、成为负责任的领导者

## 工作流

```
定义观测对象与阈值（口径直接复用 evaluation 模块的指标定义卡）
  → 采集数据（定期采集 / 事件驱动）
  → 数据 → 信息：与基线比较，计算偏差，判定级别
  → 信息 → 报告：按受众裁剪内容与粒度
  → 触发预警（绿 / 黄 / 红三档 + 升级路径）
  → 记录日志（事件流，不可事后补记）
  → 异常闭环（列入问题日志 → 纠正措施 → 验证关闭）
  → 输出 Markdown 报告
```

> **口径唯一原则**：观测所用的指标口径必须与 evaluation 模块完全一致。两处口径不一致，是项目报告失真的首要原因。

## 输入要求

- **必需**：指标定义卡（来自 evaluation 模块）、进度基准、阈值表
- **推荐**：上一周期报告、问题日志、变更请求台账
- **可选**：客户方考核周期、合规事件记录、资源负荷表

若输入不足，追问以下要素（最多 2 轮）：
1. 报告受众与频率（决策层 / 管理层 / 执行层）
2. 哪些指标属于"红线"（触碰即上报）
3. 数据采集责任人与采集工具
4. 异常上报的升级路径与时限要求

## 观测三件套

| 要素 | 回答的问题 | 项目场景对应物 | 保留要求 |
|------|-----------|---------------|----------|
| **日志 Events** | 发生了什么 | 会议纪要、变更请求、问题日志、AE/PV 记录、验收记录 | 按时间顺序不可篡改，改动须留痕 |
| **指标 Metrics** | 现在处于什么状态 | 里程碑达成率、SLA、服务完成量、成本消耗、人效 | 定期采集，历史序列可追溯 |
| **追踪 Traces** | 一个事项端到端走了多久 | 单个患者：入组 → 首次服务 → 留存至 N 月；单张变更：提出 → 评估 → 批准 → 关闭 | 记录每个环节的时间戳与责任人 |

三件套缺一不可：只有指标会"看见偏差但不知道为什么"，只有日志会"知道发生了什么但看不见趋势"。

## 阈值与告警分级

| 级别 | 触发条件 | 响应时限 | 处置与升级路径 |
|------|----------|----------|---------------|
| **绿** | 偏差 ≤ 5%，且在轨 | 常规周期报告 | 项目内记录，不升级 |
| **黄** | 偏差 5% – 15%，或趋势连续两期恶化 | 24 小时内 | 项目经理处置，出纠偏措施，下期复验 |
| **红** | 偏差 > 15%，或触碰合规红线，或关键里程碑失守 | 当日 | 上报 PMO；评估是否触发变更请求或 CAPA |

**合规红线单列**：涉及 AE/PV 上报、GCP 文件、审计追踪、隐私保护的事项，无论偏差大小，一律按红色处理并同步合规责任人。

## 报告受众裁剪

同一套数据，三份报告。**不要用一份报告喂所有受众**。

| 受众 | 频率 | 篇幅 | 内容重点 |
|------|------|------|----------|
| 决策层（药企客户 / 公司管理层） | 月度 | 1 页 | 红黄绿状态 + 3 个关键偏差 + 需要的决策事项 |
| 管理层（PMO / 部门负责人） | 双周 | 3 页 | 指标趋势 + 偏差根因 + 行动项进度 + 资源负荷 |
| 执行层（项目经理 / 驻点专员） | 周 | 明细 | 明细数据 + 待办清单 + 风险提示 |

## 观测清单（可裁剪）

| 观测对象 | 指标 | 采集频率 | 黄线 | 红线 | 责任人 | 预警动作 |
|----------|------|----------|------|------|--------|----------|
| 服务交付 | 服务按时完成率 | 周 | < 95% | < 90% | 项目经理 | 排查专员负荷与排班 |
| 患者留存 | 阶段脱落率 | 月 | > 目标 +5% | > 目标 +10% | 个案管理师 | 分析脱落原因，调整触达策略 |
| 数据质量 | 随访记录及时率 | 周 | < 95% | < 85% | 数据专员 | 逐条回溯原始记录 |
| 合规 | AE 上报及时率 | 事件触发 | < 100% | < 100% | 合规责任人 | 即时上报，同步启动 CAPA 评估 |
| 成本 | 累计成本消耗率 | 月 | 超支 5% | 超支 10% | 项目经理 | 复核按服务量折算口径 |

> 上表为模板，实际阈值须结合合同 SLA 与客户考核条款确定，并在报告中标注阈值来源。

## 裁剪指导

| 开发方法 | 观测频率 | 报告粒度 | 特殊处理 |
|----------|----------|----------|----------|
| **预测型** | 周采集 + 月报告 | 全量观测清单 | 正式月度状态报告，含 EVM 与偏差趋势 |
| **适应型（敏捷）** | 每次迭代 + 每日站会信号 | 看板级 | 迭代燃尽 + 阻塞项清单，口径与迭代目标对齐 |
| **混合型** | 里程碑按预测型、迭代按适应型 | 分层 | 上层用状态报告，执行层用看板 |

多项目并行时（PMO 视角），先做**一致性检查**：各项目的指标口径、采集频率、报告格式是否统一。口径不统一的项目不可横向比较。

详细裁剪建议见 [tailoring-guide.md](tailoring-guide.md)。

## 工具使用

- 读取指标定义卡与基线：Read 工具
- 检索历史状态报告、问题日志：Grep 工具
- 趋势计算、偏差与阈值批量判定：Bash 运行 Python 脚本
- 查询合规要求与上报时限：WebSearch（须回溯官方源原文二次印证）
- AI 辅助（Assistance 层）：异常模式识别、报告内容按受众裁剪
- AI 增强（Augmentation 层）：偏差趋势预测、提前触发预警、根因推断
