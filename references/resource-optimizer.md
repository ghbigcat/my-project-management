# 资源优化器 (resource-optimizer)

## 定位

基于人员能力矩阵和任务需求，计算最优任务分配方案并评估负载均衡。适用于项目规划阶段和资源调整时。

> **PMBOK 第八版对齐**：Resources 绩效域 · Planning 聚焦领域 · 原则：建设赋能文化、成为负责任的领导者、融入可持续发展

## 工作流

```
输入人员信息、技能矩阵和任务列表
  → 确定项目开发方法 → 参考裁剪指导调整资源管理方式
  → 计算人员-任务匹配度
  → 计算当前负载分布
  → 评估能力建设机会（第八版"建设赋能文化"原则）
  → 评估资源可持续性（第八版"融入可持续发展"原则）
  → 生成最优分配方案
  → 输出分配方案 + 负载均衡表
```

## 输入要求

- **必需**：任务清单（含工时估算、技能要求、优先级）
- **必需**：人员清单（含可用工时、技能水平）
- **推荐**：组织结构、汇报关系、人员偏好、职业发展目标

若输入不足，追问以下要素（最多 2 轮）：
1. 团队成员的可用工时（全职/兼职/共享）
2. 技能等级定义标准
3. 是否有不可变更的分配约束
4. 项目开发方法（预测型/适应型/混合型）— 影响资源分配方式
5. 团队能力建设需求（第八版新增）— 是否有人员需要通过项目锻炼特定技能

## 技能矩阵模型

### 技能等级定义

| 等级 | 标签 | 定义 |
|------|------|------|
| 4 | 专家 | 可独立完成并指导他人，处理复杂问题 |
| 3 | 熟练 | 可独立完成标准任务，偶尔需要指导 |
| 2 | 入门 | 需要指导才能完成，有基础认知 |
| 1 | 了解 | 有概念认知，无法独立完成 |
| 0 | 无 | 无相关技能 |

### 匹配度计算

任务技能要求与人员技能等级的匹配度：

```
匹配度 = Σ(人员技能等级 ≥ 任务要求等级 ? 1 : 0) / 任务要求的技能总数

综合匹配分 = Σ(人员技能等级 / 任务要求等级) / 技能数 × 100
```

- **综合匹配分 ≥ 80**：高度匹配
- **60-79**：基本匹配
- **< 60**：匹配度不足，需要培训或支援

## 负载均衡分析

### 负载率计算

```
人员负载率 = 已分配任务总工时 / 可用工时 × 100%
```

| 负载率 | 状态 | 建议 |
|--------|------|------|
| > 120% | 超负荷 | 立即重新分配，有 burnout 风险 |
| 90-120% | 高负荷 | 密切监控，预留缓冲 |
| 70-90% | 理想 | 保持 |
| 50-70% | 低负荷 | 可承担更多任务 |
| < 50% | 闲置 | 考虑释放或转岗 |

### 均衡度指标

```
负载标准差 = √(Σ(个人负载率 - 平均负载率)² / 人数)

均衡系数 = 1 - (负载标准差 / 平均负载率)
```

- 均衡系数 > 0.8：分配均衡
- 0.5-0.8：一般，可优化
- < 0.5：不均衡，需要调整

## 赋能文化建设（第八版原则 6 — "建设赋能文化"）

资源分配不仅追求效率，还须兼顾团队能力建设和赋能：

### 能力建设机会评估

在分配任务时，识别"成长型分配"机会：

| 分配类型 | 说明 | 适用场景 |
|----------|------|----------|
| 最佳匹配分配 | 技能等级 ≥ 要求，效率最高 | 关键路径任务、高风险任务 |
| 成长型分配 | 技能等级略低于要求（差 1 级），有指导人 | 非关键路径、有缓冲的任务 |
| 跨域轮岗 | 分配到非擅长领域，配导师 | 人员有明确跨领域发展意愿 |

### 成长型分配规则

- 每位成员成长型分配任务占比 ≤ 30%（防止过高的学习成本影响交付）
- 成长型分配须搭配指导人（技能等级 ≥ 3 的同任务人员）
- 关键路径任务不使用成长型分配

### 团队赋能度评分

| 维度 | 评估问题 | 评分 |
|------|----------|------|
| 自主权 | 成员是否有决策空间，而非仅执行指令？ | 1-5 |
| 能力成长 | 分配方案是否提供了学习机会？ | 1-5 |
| 指导支持 | 入门级人员是否有明确的指导人？ | 1-5 |
| 反馈闭环 | 是否有定期反馈和调整机制？ | 1-5 |

> 团队赋能度均分 ≥ 3.5 为合格，< 3 需要调整分配方案。

## 资源可持续性评估（第八版原则 5 — "融入可持续发展"）

| 维度 | 评估问题 | 影响 |
|------|----------|------|
| 人员可持续 | 是否有成员长期超负荷？是否有 burnout 预警？ | 高/中/低 |
| 技能可持续 | 团队是否存在单点依赖（某技能仅 1 人具备）？ | 高/中/低 |
| 资源消耗 | 物理资源（设备、材料）选择是否考虑环境友好？ | 高/中/低 |

## 优化策略

1. **技能优先**：高匹配度优先分配，确保关键任务由最合适的人承担
2. **负载均衡**：在匹配度相近时，优先分配给负载较低的人员
3. **关键路径保护**：关键路径上的任务分配最强资源
4. **发展与风险平衡**：适当安排"入门"级人员搭配"专家"级，兼顾培养和风险控制（第八版"建设赋能文化"原则）
5. **预留缓冲**：核心人员保留 10-20% 工时作为应急缓冲
6. **能力建设**（第八版新增）：在非关键路径上创造成长型分配机会
7. **可持续资源**（第八版新增）：避免长期超负荷，消除单点依赖，考虑环境友好资源选择

## 裁剪指导

根据项目开发方法调整资源管理方式：

| 开发方法 | 资源分配方式 | 赋能重点 | 特殊处理 |
|----------|-------------|----------|----------|
| **预测型** | 前置分配，按角色和技能匹配 | 技能矩阵 + 培训计划 | 正式资源分配表，变更需走流程 |
| **适应型（敏捷）** | 自组织团队，迭代内自领任务 | 跨功能团队、T 型人才 | 团队整体能力 > 个人匹配度，鼓励跨领域学习 |
| **混合型** | 上层预测型分配 + 执行层自组织 | 两者结合 | 框架角色前置分配，执行任务自组织 |

详细裁剪建议见 [tailoring-guide.md](tailoring-guide.md)。

## 工具使用

- 读取人员/任务数据：Read 工具（支持 Excel/CSV/Markdown）
- 匹配度与负载计算：Bash 运行 Python 脚本
- 搜索已有资源分配记录：Grep 工具
- AI 辅助（Assistance 层）：自动识别能力建设机会和单点依赖
- AI 增强（Augmentation 层）：模拟多种分配方案，推荐最优组合
