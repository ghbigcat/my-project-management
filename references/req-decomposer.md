# 需求拆解助手 (req-decomposer)

## 定位

将模糊需求描述转化为结构化、可执行的任务清单（WBS）。适用于项目启动阶段或需求变更时。

> **PMBOK 第八版对齐**：Scope 绩效域 · Initiating/Planning 聚焦领域 · 原则：采用全局视角、聚焦价值、将质量融入过程

## 工作流

```
输入用户需求描述
  → (如有附件) 读取并分析附件
  → 确定项目开发方法（预测型/适应型/混合型）→ 参考裁剪指导调整分解方式
  → 拆解为 WBS 结构（层级化任务分解）
  → 价值映射：每个工作包标注对项目价值目标的贡献
  → 可持续性影响评估（社会/环境/经济）
  → 标注优先级和工时估算
  → 输出结构化 Markdown 报告
```

## 输入要求

- **必需**：需求描述文本（口语化或半结构化均可）
- **可选**：需求文档附件（PDF/Word/Markdown）、已有项目背景信息

若输入信息不足，主动追问以下要素（最多追问 2 轮，仍不足则基于已有信息合理假设并标注）：
1. 项目目标和预期价值成果（不仅是交付物，而是期望创造的价值）
2. 关键约束（时间、预算、资源）
3. 已知的相关方和依赖
4. 项目开发方法（预测型/适应型/混合型）— 若未明确，根据需求特征推断

## 拆解方法

采用 PMBOK 第八版 WBS 创建方法，结合 INVEST 原则验证任务质量：

### WBS 分解规则

1. **分解至工作包级别**：最底层任务可独立估算工时和分配（通常 1-5 个工作日）
2. **100% 原则**：子任务之和 = 父任务全部范围，不遗漏不重叠
3. **滚动式规划**：近期任务详细分解，远期任务粗粒度占位
4. **价值导向**（第八版新增）：每个工作包应能追溯到一个或多个项目价值目标，避免"有产出无价值"的分解

### 价值映射（第八版"聚焦价值"原则）

每个一级任务须关联项目价值目标：

| 价值目标 | 对应任务 | 价值贡献说明 |
|----------|----------|-------------|
| {价值目标 1} | {任务编号范围} | {这些任务如何实现该价值} |
| {价值目标 2} | {任务编号范围} | {这些任务如何实现该价值} |

> 项目价值目标定义：项目交付物为相关方带来的可衡量收益（如效率提升 X%、患者满意度提升 Y 分）。

### 任务卡片字段

每个工作包须包含：

| 字段 | 说明 |
|------|------|
| 任务编号 | 层级编码，如 1.2.3 |
| 任务名称 | 动词+名词，如"编写需求规格说明书" |
| 描述 | 1-2 句话说明做什么、交付什么 |
| 优先级 | 高/中/低（基于 MoSCoW 方法） |
| 工时估算 | 人天或人时，标注估算依据 |
| 前置依赖 | 依赖的其他任务编号 |
| 验收标准 | 可验证的完成条件（SMART 原则）— 体现"将质量融入过程"原则 |
| 价值贡献 | 该任务对项目价值目标的贡献（简述） |

### INVEST 验证

对每个工作包检查：
- **I**ndependent：独立可完成
- **N**egotiable：可协商调整
- **V**aluable：对项目目标有明确价值（第八版强调：可追溯到价值目标）
- **E**stimable：可估算工时
- **S**mall：粒度适中
- **T**estable：有明确验收标准

## 可持续性影响评估（第八版原则 5）

在 WBS 拆解完成后，对项目整体进行可持续性影响评估：

| 维度 | 评估问题 | 影响等级 | 缓解措施 |
|------|----------|----------|----------|
| 社会 | 项目是否影响特定群体（患者、员工、社区）？ | 高/中/低/无 | |
| 环境 | 项目是否涉及资源消耗、废弃物、碳排放？ | 高/中/低/无 | |
| 经济 | 项目是否影响组织财务可持续性或行业生态？ | 高/中/低/无 | |

> 若三个维度均为"无"或"低"，可简注一行说明，无需展开表格。

## 裁剪指导

根据项目开发方法调整 WBS 分解方式：

| 开发方法 | WBS 分解方式 | 分解深度 | 特殊处理 |
|----------|-------------|----------|----------|
| **预测型** | 完整层级化 WBS，一次性分解至工作包 | 深（3-5 层） | 每个工作包有明确交付物和验收标准 |
| **适应型（敏捷）** | 产品待办列表（Product Backlog）+ 迭代分解 | 浅（2 层：Epic → Story） | 使用用户故事格式（As a... I want... so that...），INVEST 验证为主 |
| **适应型（看板）** | 看板列定义 + 工作项卡片 | 浅（1-2 层） | 按价值流分解，强调流动效率 |
| **混合型** | 预测型框架 + 适应型执行 | 中（2-3 层） | 上层预测型 WBS，下层迭代分解 |

详细裁剪建议见 [tailoring-guide.md](tailoring-guide.md)。

## 工具使用

- 读取附件：Read 工具
- 搜索行业最佳实践：WebSearch（如"医疗健康项目 WBS 最佳实践"）
- 数据处理/时间线计算：Bash 运行 Python 脚本
- AI 辅助（Augmentation 层）：利用本能力内置逻辑进行价值映射分析和可持续性影响评估
